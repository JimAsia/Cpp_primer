(a) inline bool eq(const BigInt&, const BigInt&) {...}：声明和定义都放在头文件（.h/.hpp）中。
(b) void putValues(int *arr, int size);：声明放在头文件（.h/.hpp）中，定义（函数体）放在源文件（.cpp）中。

为什么 inline 函数放在头文件？

内联机制：inline 函数（内联函数）的目的是为了在调用处直接展开代码，以减少函数调用的开销。

可见性：编译器在编译某个源文件（.cpp）时，如果遇到对 eq 的调用，必须能够看到它的函数体（定义）才能进行内联展开。

避免链接错误：如果只把 inline 函数的定义放在某个源文件（比如 a.cpp）中，并在头文件中只放声明，那么当另一个源文件 b.cpp 包含该头文件并调用 eq 时，编译器看不到定义，无法内联。链接器可能会报“未定义引用（undefined reference）”错误。

ODR（一次定义规则）的特例：普通函数不能多次定义，但 inline 函数允许在多个编译单元（源文件）中出现相同的定义。前提是定义必须完全一致。因此，把 inline 函数的定义放在头文件中被多个源文件包含，是标准允许且唯一正确的做法。



函数声明（如 void putValues(int *arr, int size);）只是告诉编译器有这个函数存在，具体实现在哪里链接器会去管。它没有生成实际的机器码，因此放在头文件中被多个源文件包含是安全的。

函数定义（包含函数体的代码）会生成机器码。如果放在头文件中，当这个头文件被多个源文件（比如 a.cpp 和 b.cpp）包含时，putValues 的函数体就会被编译多次，导致在链接阶段出现“多重定义（multiple definition）”错误。

为了遵循ODR（One Definition Rule，一次定义规则），整个程序中，每个普通（非inline、非模板、非constexpr）函数只能有一次定义。因此，定义必须放在唯一的源文件（.cpp）中，而头文件中只保留声明供其他源文件使用。


内联函数、模板、constexpr 函数、类的定义：放头文件（为了多处可见和展开）。

普通函数声明、外部变量声明：放头文件（供全局使用）。

普通函数定义、全局变量定义：放源文件（遵循一次定义规则，避免重复）。
