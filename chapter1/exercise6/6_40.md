(b) 是错误的。

原因分析：
在C++中，带有默认参数的函数必须遵循“从右向左连续定义”的规则。也就是说，如果一个参数设定了默认值，那么它右边的所有参数都必须有默认值。

声明 (a) int ff(int a, int b = 0, int c = 0); 中，b 和 c 都有默认值，且位于参数列表的右侧，符合规则，是正确的。

声明 (b) char *init(int ht = 24, int wd, char bckgrnd); 中，ht 有默认值，但它右边的 wd 和 bckgrnd 却没有默认值。这违反了“从右向左连续定义”的规则，会导致编译错误，因此是错误的。

// 6.41
char *init(int ht, int wd = 80, char bckgrnd = ' ');
init(); 是非法的。

原因：
函数 init 的第一个参数 ht 没有默认值。在调用 init() 时没有提供任何参数，导致缺少必要的实参 ht，编译器会报错（参数数量不匹配）。

哪个调用虽然合法但显然与程序员的初衷不符？为什么？

答案：(b) init(24, 10); 和 (c) init(14, '*'); 虽然合法，但显然与程序员的初衷不符。
调用 (b) init(24, 10);：这里 24 传给了 ht，10 传给了 wd，bckgrnd 使用默认值 ' '。语法完全合法。但从程序员的角度来看，10 是一个整数，把它传给表示宽度的 wd 是合理的，但如果程序员的本意是想把背景字符 bckgrnd 设置为某个值（比如 ASCII 码为10的换行符），那么这个传参位置是错误的，这会导致宽度被意外修改为10，而背景没有变化。

调用 (c) init(14, '*');：这里 14 传给了 ht，字符 '*' 被隐式转换为整型（ASCII码 42）传给了 wd，bckgrnd 仍然使用默认值 ' '。语法合法，能编译通过。但程序员的初衷显然是想把背景字符 bckgrnd 设置为 '*'，却错误地把它写在了第二个参数的位置（wd 的位置）。结果是背景依然是空格，而宽度 wd 变成了42，这显然与初衷严重不符。如果要实现初衷，正确的调用应该是 init(14, 80, '*'); 或者结合默认参数使用 init(14, 80, '*'); 甚至可以写成 init(14, 80, '*');（根据具体默认值情况，最直接的是 init(14, 80, '*');，或者如果只改背景，使用 init(0, 80, '*'); 假设第一个参数必需）。
