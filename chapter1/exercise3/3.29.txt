1.安全性差，极易发生越界（最常见的问题）
数组：完全不做边界检查。如果你声明了 int a[5]，但访问了 a[10]，编译器不会报错。这在运行时会导致未定义行为（通常是程序崩溃或数据损坏）。
vector：当你使用 at() 方法访问元素时（如 vec.at(10)），如果发生越界，它会抛出一个 std::out_of_range 异常，让你能优雅地捕获并处理错误。
2.大小固定，缺乏灵活性
数组：大小在编译期就必须确定（或者作为 VLA 在运行时确定后不可改变）。如果你需要动态添加元素，你只能手写代码去申请一块更大的新内存，把旧数据拷贝过去，再释放旧内存。这非常繁琐且容易出错。
vector：支持动态扩容。你可以随时调用 push_back()、insert() 或 resize() 来改变数组大小。vector 内部会自动帮你处理内存的重新分配和数据拷贝，程序员只需要关注业务逻辑。
3.无法直接传递大小信息（退化问题）
数组：当数组作为参数传递给函数时，它会退化（decay）为一个指针。这意味着函数内部完全不知道这个数组原本有多大，你必须额外传一个参数（如 int size）来告诉函数它的长度。
vector：对象本身就携带了大小信息。你随时可以调用 .size() 方法来获取当前包含多少个元素，极其方便。
4.资源管理复杂，容易内存泄漏
数组：如果你需要动态数组（比如 int* a = new int[1000];），你必须记住在用完之后使用 delete[] a; 手动释放它。如果代码逻辑复杂（例如中间抛出了异常，或者提前 return），很容易忘记释放内存，导致内存泄漏。
vector：遵循 RAII (资源获取即初始化) 原则。它是对象，在生命周期结束时（例如离开作用域时）会自动释放其内部占用的内存，几乎不可能发生内存泄漏。
5.不支持直接的赋值、比较和拷贝
数组：你不能直接用 = 将一个数组赋给另一个数组（如 int a[5], b[5]; a = b; 是错误的），也不能直接用 == 比较两个数组是否相等。如果要拷贝，你必须使用 memcpy 或写循环一个一个复制。
vector：原生支持赋值运算符 =、比较运算符 == 和 < 等。一行代码就能完成深拷贝或比较，极其直观。
