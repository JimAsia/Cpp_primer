# 练习 7.55

```cpp
struct Data {
    int ival;
    std::string s; // 注意这里的 string 类型
};
```

字面值常量类要求所有数据成员必须是**字面值类型**（literal type）。在这个类中，`int ival` 是字面值类型，但 `std::string s` **不是**字面值类型。

## 📝 为什么 `std::string` 不是字面值类型？

在 C++11 中，一个类型要被称为"字面值类型"，它必须满足以下条件之一：

- 是算术类型（如 `int`、`double`）、指针、引用等；
- 是字面值常量类（具有 `constexpr` 构造函数，且所有成员都是字面值类型）。

`std::string` 不满足上述条件，原因如下：

- **没有 `constexpr` 构造函数**：`std::string` 内部需要动态分配内存，它的构造函数无法在编译期完成。
- **析构函数不是平凡的（trivial）**：`std::string` 需要释放动态内存，其析构函数有实际的逻辑，不是在编译期可以简单省略的。

因此，由于 `Data` 类中包含了一个非字面值类型的成员 `std::string`，它不能被作为字面值常量类。

## 💡 知识点拓展：如何把 `Data` 变成字面值常量类？

如果要让 `Data` 类成为字面值常量类，需要满足以下所有条件：

1. 数据成员都必须是字面值类型。
2. 类必须至少含有一个 `constexpr` 构造函数（如果是聚合类且满足条件，编译器会提供隐式的 `constexpr` 默认构造函数）。
3. 如果数据成员含有类内初始值，则内置类型成员的初始值必须是常量表达式；如果是类类型成员，必须使用成员自己的 `constexpr` 构造函数。
4. 类必须使用析构函数的默认定义。

**修改方案**：将 `std::string s` 换成 `const char* s` 或其他字面值类型，它就符合字面值常量类的标准了：

```cpp
struct Data {
    int ival;
    const char* s; // 现在它是一个字面值常量类了
};
```

或者，如果一定要存字符串，可以改用自定义的、带有 `constexpr` 构造函数的类，或者使用固定大小的字符数组。

## 总结

`Data` 是聚合类，不是字面值常量类，关键卡点就在于 `std::string` 不属于字面值类型。
