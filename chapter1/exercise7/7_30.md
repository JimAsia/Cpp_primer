class Person {
    string name;
public:
    void setName(string name) {
        this->name = name;  // 显式使用 this
        // name = name;     // 这样会出错，参数名遮蔽了成员名
    }
};

显式使用 this 的优点
消除命名冲突：当参数名与成员名相同时，this->name = name 可以明确区分成员变量和局部变量/参数，避免歧义。
提高可读性：在复杂代码中，this->member 能让人一眼看出这是成员变量而非局部变量，增强代码自文档化。
支持链式调用：返回 *this 可以实现链式操作，如 obj.setA(1).setB(2).setC(3)。
模板编程中必要：在类模板中访问基类成员时，有时必须使用 this-> 来告诉编译器这是一个依赖名称。
显式使用 this 的缺点
代码冗余：在大多数情况下，编译器会自动通过 this 访问成员，显式写出显得多余，增加代码量。
降低简洁性：如果每个成员访问都写 this->，代码会变得冗长，影响阅读流畅性。
风格争议：很多编码规范（如 Google C++ Style）不推荐滥用 this->，认为好的命名约定（如成员加 m_ 前缀）就能解决歧义问题。
