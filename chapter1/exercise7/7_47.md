# 练习 7.47

## ✅ 设为 `explicit` 的优点（为什么应该这样做）

### 1. 避免意外和难以发现的错误

如果允许隐式转换，下面的代码会合法编译：

```cpp
Sales_data item;
item.combine("978-0-321-71495-6"); // 隐式将字符串字面量转换成 Sales_data 对象！
```

这里 `combine` 函数原本期待的是一个 `Sales_data` 对象，但编译器偷偷帮你用字符串构造了一个临时的 `Sales_data` 对象。这可能完全不是程序员的本意，从而隐藏了逻辑错误。

### 2. 代码意图更清晰

强制显式调用构造函数，让代码的阅读者能一眼看出类型转换的发生，提高了代码的可读性：

```cpp
item.combine(Sales_data("978-0-321-71495-6")); // 明确构造，意图清晰
```

### 3. 符合 C++ 的最佳实践

在 C++ 中，除非有非常明确且安全的理由（例如 `std::string` 接受 `const char*` 这种为了兼容 C 语言的转换），单参数构造函数通常都应该声明为 `explicit`。这是现代 C++ 编码规范（如 Google C++ Style Guide、C++ Core Guidelines）的强烈推荐。

## ❌ 设为 `explicit` 的缺点

### 1. 失去了一些便利性

不能直接把 `std::string` 传给接受 `Sales_data` 参数的函数，也不能直接用 `=` 初始化：

```cpp
Sales_data item = "978-0-321-71495-6"; // 错误：explicit 禁止这种拷贝初始化
```

必须手动显式构造：

```cpp
Sales_data item("978-0-321-71495-6"); // 正确：直接初始化
```

### 2. 对标准库容器的某些操作不够友好

比如在使用 `std::vector` 的 `push_back` 或者某些泛型算法时，不能利用隐式转换直接插入字符串。例如，如果隐式转换允许，你可能可以写 `vec.push_back("123")`，但设为 `explicit` 后，只能写 `vec.push_back(Sales_data("123"))`。

## 💡 总结

在《C++ Primer》的上下文和实际工程中，强烈建议为接受 `std::string` 的 `Sales_data` 构造函数加上 `explicit`。这属于"把错误扼杀在编译期"的做法，哪怕牺牲一点点代码上的便利，换来的却是更高的代码安全性和可维护性。你可以在你的代码里加上它，养成好习惯。
