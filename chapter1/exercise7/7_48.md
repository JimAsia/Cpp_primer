这两条语句都能正常编译，且行为完全一致，都是调用接受 std::string 的构造函数进行直接初始化。

我们逐行拆解来看：

1. Sales_data item1(null_isbn);
操作：直接初始化。

过程：null_isbn 本身就是一个 std::string 对象。编译器直接匹配并调用 Sales_data(const std::string&) 构造函数来初始化 item1。

explicit 的影响：因为这属于直接初始化（括号形式），即使该构造函数被声明为 explicit，这行代码也完全合法。

2. Sales_data item2("9-999-99999-9");
操作：直接初始化（包含隐式类型转换）。

过程：传入的是一个字符串字面量（const char*）。由于 Sales_data 的构造函数接受 const std::string&，编译器会先利用 std::string 的构造函数，将 "9-999-99999-9" 隐式转换为一个临时的 std::string 对象；然后再调用 Sales_data(const std::string&) 构造函数来初始化 item2。

explicit 的影响：同样因为使用了括号的直接初始化形式，即使构造函数是 explicit，这行代码依然可以编译通过。

💡 为什么题目要强调“不是 explicit”？
其实这是一个“陷阱”。题目故意假设它不是 explicit，是为了引出下面这个关键结论：

如果构造函数被声明为 explicit，上述两行代码依然完全合法。
explicit 真正禁止的是拷贝初始化（使用 = 号），例如：

cpp
Sales_data item3 = "9-999-99999-9"; // 如果构造函数是 explicit，这里会报错！
Sales_data item4 = null_isbn;       // 如果构造函数是 explicit，这里也会报错！
或者在函数调用时传递隐式转换：

cpp
void func(Sales_data s);
func("9-999-99999-9"); // 如果构造函数是 explicit，这里会报错！
总结
这道题的核心考查点是：explicit 关键字只对拷贝初始化（=）生效，对直接初始化（()）没有影响。 你这两行代码由于使用了括号直接初始化，无论如何都会成功创建对象并调用相应的构造函数。
