# 练习 8.12

**题目**：我们为什么没有在 `PersonInfo` 中使用类内初始化？

**标准答案**：因为 `PersonInfo` 只是一个简单的**数据聚合类（Aggregate Class）**，它的成员在创建后总是会被立即重新赋值，使用类内初始化不仅多此一举，还会破坏其聚合类的特性。

结合书中 8.1.2 节的上下文，我们来详细拆解原因。

## 1. 成员总是被立即覆盖 / 填充

在书中的 `read` 函数里，`PersonInfo` 是这样被使用的：

```cpp
struct PersonInfo {
    string name;
    vector<string> phones;
};

// read 函数内部
PersonInfo info;                  // 1. 创建一个空的 PersonInfo 对象
record >> info.name;              // 2. 立即从输入流中读取姓名并覆盖 name
while (record >> word) {
    info.phones.push_back(word);  // 3. 立即向 phones 中追加号码
}
```

由于在创建对象后，`name` 和 `phones` 会马上被实际数据赋值或追加，给它们设置默认初始值（例如 `string name = "";` 或 `vector<string> phones{};`）是毫无意义的冗余操作。因为 `string` 和 `vector` 默认构造函数本身就会产生合法的空状态。

## 2. 保持"聚合类"的特性（C++11 标准）

在本书基于的 C++11 标准下（这是关键）：

**聚合类（Aggregate Class）** 要求：没有用户提供的构造函数、没有私有或受保护的非静态数据成员、没有基类、没有虚函数，且**不能有类内初始化器**。

如果给 `name` 或 `phones` 加了类内初始化，`PersonInfo` 就不再是聚合类了。

一旦不是聚合类，你就不能使用聚合初始化（例如 `PersonInfo p = {"Alice", {"123", "456"}};`），这会限制该结构体的灵活性和轻量级特性。

> _注：C++14 之后放宽了限制，允许聚合类有类内初始化器，但在 C++11 中不行。_

## 3. 设计意图：它只是个"数据载体"

`PersonInfo` 的设计目的非常纯粹：就是从文件 / 输入流中解析数据并打包，没有需要维护的不变式（Invariant），也没有复杂的业务逻辑。对于一个没有默认状态需求的纯数据结构，不需要画蛇添足地加类内初始化。

## 总结对比

- 如果是一个**普通类**（比如 `class Date`），你可能需要 `int month = 1;` 来防止未初始化的随机值。
- 但对于 `PersonInfo`，创建它就是为了立刻装载数据，所以**不加类内初始化**才是最简洁、最符合其设计意图的做法。
