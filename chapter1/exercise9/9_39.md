vector<string> svec;
svec.reserve(1024);           // 1. 预分配至少 1024 个元素的连续内存，此时 size=0, capacity>=1024
string word;
while (cin >> word)           // 2. 从标准输入读取单词
    svec.push_back(word);     //    将单词添加到 svec，若单词数不超过 1024 则不会重新分配内存
svec.resize(svec.size() + svec.size() / 2); // 3. 将容器大小调整为原来的 1.5 倍

创建一个空的 string 类型的 vector。

reserve(1024) 显式要求分配足够容纳 1024 个元素的内存，避免了在后续读取过程中频繁扩容。

循环读取输入，并将单词压入 svec。

退出循环后，resize 会将 svec 的 size 扩大到当前大小的 1.5 倍。如果扩容后的 size 超过当前 capacity，则会触发重新分配内存；否则，多出来的元素将被进行值初始化（对于 string 来说就是空字符串）。

练习 9.40：如果上一题中的程序读入了 256 个词，在 resize 之后容器的 capacity 可能是多少？如果读入了 512 个、1000 个或 1048 个词呢？
注：因为 svec.reserve(1024)，初始 capacity 至少为 1024，通常就是 1024。

读入 256 个词：

读入后 size = 256。

resize(256 + 128) = resize(384)。

因为 384 <= 1024，不会触发内存重新分配。

capacity 依然是 1024，size 变为 384。

读入 512 个词：

读入后 size = 512。

resize(512 + 256) = resize(768)。

因为 768 <= 1024，不会触发内存重新分配。

capacity 依然是 1024，size 变为 768。

读入 1000 个词：

读入后 size = 1000。

resize(1000 + 500) = resize(1500)。

因为 1500 > 1024，会触发内存重新分配。capacity 将变为大于等于 1500 的某个值（在 GCC 中通常翻倍为 2048，在 MSVC 中通常按 1.5 倍变为 1536）。

capacity 可能是 2048 或 1536（取决于编译器实现），size 变为 1500。

读入 1048 个词：

在读入过程中，当压入第 1025 个词时，由于超出了 reserve 的 1024，vector 就已经进行过一次扩容（capacity 通常变为 2048 或 1536）。

读入完毕后 size = 1048。

resize(1048 + 524) = resize(1572)。

此时需要根据之前的扩容情况来判断：

如果上一步容量扩到了 2048，由于 1572 <= 2048，不会再次扩容，capacity 是 2048。

如果上一步容量扩到了 1536，由于 1572 > 1536，会再次触发扩容，capacity 可能变为 3072（1536*2）或 2304（1536*1.5）。

因此，capacity 可能是 2048、3072 或 2304 等，size 变为 1572。
