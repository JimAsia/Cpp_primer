# 练习 9.9

## 1. `begin()`

- **返回类型**：如果容器是非 `const` 的，它返回 `iterator`；如果容器是 `const` 的，它返回 `const_iterator`。
- **作用**：返回指向容器第一个元素的迭代器。对于非 `const` 容器，你可以通过这个迭代器读取和修改元素的值。

## 2. `cbegin()`（C++11 引入）

- **返回类型**：始终返回 `const_iterator`（常量迭代器）。
- **作用**：无论容器本身是不是 `const` 的，`cbegin()` 都只返回一个常量迭代器。你只能通过它读取元素，不能修改元素的值。

## 对比

| 成员函数 | 非 const 容器 | const 容器 | 能否修改元素 |
| --- | --- | --- | :---: |
| `begin()` | 返回 `iterator` | 返回 `const_iterator` | ✅（非 const 容器时） |
| `cbegin()` | 返回 `const_iterator` | 返回 `const_iterator` | ❌ |

## 💻 代码示例对比

假设有一个普通的 `vector<int>`：

```cpp
vector<int> v = {1, 2, 3};

// 使用 begin()
auto it1 = v.begin();
*it1 = 10; // ✅ 合法：可以修改元素的值，v 变成 {10, 2, 3}

// 使用 cbegin()
auto it2 = v.cbegin();
// *it2 = 20; // ❌ 编译错误！不能通过 const_iterator 修改元素
```

## 💡 为什么要用 cbegin()？

- **提高代码可读性**：当你只想遍历容器读取数据而不打算修改时，用 `cbegin()` 能向其他阅读代码的人明确传达"我只读"的意图。
- **避免意外修改**：用 `const_iterator` 可以防止在代码逻辑中意外篡改了数据，编译器会帮你把关。
- **配合 auto 关键字**：在 C++11 中，如果你只写 `auto it = v.begin()`，推导出来的类型是 `iterator`，允许修改。如果你希望推导出来是 `const_iterator`，就必须显式写 `v.cbegin()`。
